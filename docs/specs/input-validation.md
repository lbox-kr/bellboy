# 입력값 문법 · 검증 (spec)

사이트/규칙 입력 필드의 문법 정본. 구현은 `src/validation.ts`(UI)와
`src-tauri/src/validate.rs`(백엔드 방어) 두 곳이며, **두 파일은 같은 규칙을 유지해야 한다.**

## 왜 필요한가

필드마다 기대 문법이 다르고, 그 차이가 UI 에 드러나지 않는다. 특히 스킴은
**넣으면 안 되는 곳**(`domain`)과 **넣어야 하는 곳**(원격 `target`)이 나뉜다.
검증이 없으면 잘못된 값이 `config.json` → `Caddyfile` → `/etc/hosts` 까지 흘러가고,
실패는 저장 시점이 아니라 Caddy 리로드·요청 시점에 나타나 원인 추적이 어렵다.

## 필드별 문법

| 필드 | 허용 | 금지 |
|---|---|---|
| `Site.domain` | 소문자·숫자·하이픈 라벨 (`myapp.test`) | 스킴, 포트, 경로, 공백, 와일드카드, 예약어(`localhost`·`local`·`broadcasthost`), 중복 |
| `Site.upstream`, `Rule.target`, `ProxyEnvPreset.target` | `[scheme://]host[:port]` | 경로·쿼리, 공백, `http`/`https` 외 스킴 |
| `Rule.path` | `/` 로 시작하는 Caddy matcher (`/api/*`) | 공백, 스킴, 슬래시 누락 |
| `Rule.root` | 절대 경로 `/…` 또는 `~/…` | 상대 경로 |
| `ProxyEnvPreset.name` | 1자 이상 | 공란 |

### 스킴 규칙

- **로컬 호스트**(`localhost`, `127.0.0.1`, `0.0.0.0`, `::1`, `[::1]`): 스킴 생략 가능(= http).
  단 **포트 필수** — 포트 없는 로컬 주소는 사실상 오타다.
- **그 외(원격)**: `http://` 또는 `https://` **필수**. Caddy 는 스킴이 없으면 http 로 다이얼하므로,
  https-only 오리진에 대해 요청 시점에야 실패한다.
- `https://localhost` 는 차단하지 않고 경고만(로컬 HTTPS 서버를 쓰는 경우가 있다).

### 에러 vs 경고

- **에러 → 저장 차단**: 위 표의 금지 항목 전부.
- **경고 → 저장 허용**: 점 없는 도메인, `https://localhost`, 앞 규칙과 경로가 겹치는 규칙.

## 검증이 걸리는 지점

| 지점 | 대상 | 동작 |
|---|---|---|
| `SiteDialog` / `RuleEditor` | 편집 중인 사이트 | 필드별 에러·경고 표시, 에러가 있으면 저장 버튼 비활성 |
| `apply_config` (Rust) | **활성** 사이트 전체 | 실패 시 저장·Caddyfile 쓰기·hosts 동기화 **전에** 중단하고 전체 문제 목록 반환 |

- 비활성 사이트는 백엔드 검증에서 제외한다. Caddyfile·hosts 어디에도 반영되지 않고,
  검증하면 "일단 꺼두고 나중에 고친다"가 막힌다.
- 로드(`get_config`)는 검증하지 않는다. 기존 데이터가 규칙을 어겨도 앱은 열려야 하고,
  편집 다이얼로그를 열면 그 자리에서 문제가 표시된다.

## 정규화

| 필드 | 시점 | 동작 |
|---|---|---|
| `domain` | 입력 중 | 스킴·끝 슬래시 제거, 소문자화 — 제거가 일어나면 힌트를 한 줄 노출 |
| `target`·`upstream` | blur | trim, 끝 슬래시 제거 (경로는 제거하지 않고 **에러** — 조용히 버리면 다른 곳으로 프록시된다) |
| `path` | blur | trim, 앞에 `/` 보강 |
| `root` | Caddyfile 생성(Rust) | `~/` → `$HOME` 확장, 공백 포함 시 따옴표 |

## 결정 히스토리

- **2026-08-06** — 원격 타겟의 스킴을 **에러로 차단**(자동 `https://` 보정 안 함).
  자동 보정은 http 업스트림을 조용히 https 로 바꿔 더 헷갈리는 실패를 만든다.
- **2026-08-06** — `domain` 의 스킴은 **자동 제거 + 힌트**. URL 통째로 붙여넣는 흐름이 흔해
  차단은 마찰이 크고, 조용한 수정은 버그로 읽히므로 문구를 남긴다.
- **2026-08-06** — 위 스킴 필수화에 따라 `caddyfile.rs` 의 "관리 도메인이면 `https://` 로 가정"
  암묵 규칙 제거. 스킴은 항상 입력에 존재한다.
- **2026-08-06** — `reverse_proxy` 타겟을 원본 문자열이 아니라 파싱 결과로 렌더하도록 통일.
  이전에는 관리 도메인 분기만 경로를 버리고 비관리 분기는 원본을 그대로 출력해,
  같은 입력이 분기에 따라 다르게 처리됐다.
- **2026-08-06** — `root` 의 `~/` 확장을 프론트 정규화가 아니라 Rust 렌더 시점으로 배치.
  프론트는 홈 경로를 동기적으로 알 수 없고(Tauri path API 가 async), 확장 결과를
  입력창에 되쓰면 사용자가 적은 값과 달라진다.
- **2026-08-06** — 기존 config 마이그레이션 추가(`migrate.rs`). 스킴 필수화 직후 릴리즈한 v0.1.4 에서,
  예전 방식대로 저장된 스킴 없는 타겟 때문에 `apply_config` 가 전부 거부돼 **사이트를 끄는 것조차
  불가능한 교착**이 발생했다. 로드 시 예전 렌더러가 추론하던 스킴(관리 도메인이면 `https://`,
  그 외 원격은 Caddy 기본값인 `http://`)을 채워 넣어 동작을 그대로 보존한다.
  검증만 도입하고 기존 데이터를 옮기지 않은 것이 원인이었다.
- **2026-08-06** — 검증을 TS/Rust 양쪽에 중복 구현. UI 는 즉시 피드백이 필요하고,
  백엔드는 UI 를 우회하는 경로(직접 편집한 `config.json`, 구버전 데이터)를 막아야 한다.
